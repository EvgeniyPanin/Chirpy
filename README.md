# Chirpy

Chirpy is a small Twitter-like JSON API written in Go. Users sign up, log in and post short messages ("chirps") of up to 140 characters.

## Why care?

It's a compact, readable example of a real-world Go backend built on the standard library:

- REST routing with Go 1.22+ `net/http` method and path patterns, with no framework
- PostgreSQL access through type-safe code generated by [sqlc](https://sqlc.dev)
- Schema migrations with [goose](https://github.com/pressly/goose)
- Authentication with Argon2id password hashing, short-lived JWT access tokens and revocable refresh tokens
- A payment-provider webhook ("Polka") protected by an API key

## Getting started

### Prerequisites

- Go 1.24+
- PostgreSQL
- goose: `go install github.com/pressly/goose/v3/cmd/goose@latest`
- sqlc (only needed if you change SQL queries): `go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest`

### 1. Clone and configure

```sh
git clone https://github.com/EvgeniyPanin/Chirpy.git
cd Chirpy
```

Create a `.env` file in the project root:

```sh
DB_URL="postgres://<user>:<password>@localhost:5432/chirpy?sslmode=disable"
PLATFORM="dev"              # "dev" enables POST /admin/reset
JWT_SECRET="<random secret>" # e.g. output of: openssl rand -base64 64
POLKA_KEY="<webhook api key>"
```

### 2. Create the database and run migrations

```sh
createdb chirpy
goose -dir sql/schema postgres "$DB_URL" up
```

### 3. Run the server

```sh
go run .
```

The server listens on `http://localhost:8080`. Check it with:

```sh
curl http://localhost:8080/api/healthz   # -> OK
```

### Run tests

```sh
go test ./...
```

## API overview

| Method | Path | Auth | Description |
|---|---|---|---|
| `GET` | `/api/healthz` | – | Health check |
| `POST` | `/api/users` | – | Create a user (`email`, `password`) |
| `PUT` | `/api/users` | JWT | Update your email and password |
| `POST` | `/api/login` | – | Log in, returns an access token and a refresh token |
| `POST` | `/api/refresh` | Refresh token | Get a new access token |
| `POST` | `/api/revoke` | Refresh token | Revoke a refresh token |
| `POST` | `/api/chirps` | JWT | Post a chirp (`body`, max 140 chars) |
| `GET` | `/api/chirps` | – | List chirps. Optional query: `author_id=<uuid>`, `sort=asc\|desc` (default `desc`) |
| `GET` | `/api/chirps/{chirpID}` | – | Get one chirp |
| `DELETE` | `/api/chirps/{chirpID}` | JWT | Delete your own chirp |
| `POST` | `/api/polka/webhooks` | API key | Upgrade a user to Chirpy Red |
| `GET` | `/admin/metrics` | – | Count of visits to the `/app/` page |
| `POST` | `/admin/reset` | – (`PLATFORM=dev` only) | Reset metrics and delete all users |

Authenticated endpoints expect an `Authorization` header:
`Bearer <token>` for JWT and refresh tokens, `ApiKey <key>` for the webhook.
